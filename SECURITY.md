# Security Policy

## Reporting a Vulnerability

If you discover a security vulnerability in OmniMsg, please report it responsibly.

**Do not** open a public GitHub issue for security vulnerabilities.

Instead:

1. Report the issue privately to the maintainers via GitHub Security Advisories (preferred when available) or by contacting the project owners listed in [.github/CODEOWNERS](.github/CODEOWNERS).
2. Include a clear description, steps to reproduce, and potential impact.
3. Allow reasonable time for investigation and remediation before public disclosure.

## Responsible Disclosure

We ask that you:

- Give us a reasonable period to investigate and fix the issue before public disclosure.
- Avoid accessing, modifying, or deleting data that does not belong to you.
- Avoid actions that degrade service availability (DoS, spam, brute force).

## What to Expect

- Acknowledgment of your report within a reasonable timeframe.
- Updates on the status of the investigation.
- Credit in the advisory or release notes if you wish (unless you prefer to remain anonymous).

## Supported Versions

OmniMsg is in early development. Security fixes will be applied to the active development branch (`main`) and released as the platform matures.

## Security Practices

For architectural security decisions, see [docs/adr/ADR-0012-security-model.md](docs/adr/ADR-0012-security-model.md).
